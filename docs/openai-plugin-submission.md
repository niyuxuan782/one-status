### Long description

One Status gives ChatGPT and Codex read-only access to the portable profile, active project context, and confirmed memories a user has chosen to keep in One Status. It helps users continue work across devices and AI tools without repeating preferences, current goals, open tasks, or project decisions. The initial public plugin exposes three narrowly scoped Status tools. It does not read stored credentials, API keys, passwords, OAuth tokens, raw conversations, candidate memories, or third-party service data, and it cannot modify One Status or external systems.

## Starter prompts

1. What preferences should you follow when helping me?
2. Load my current One Status context and tell me the next task.
3. Show the confirmed project memories for my active project.

## Capabilities

- Read the user's permitted portable identity, durable preferences, and Persona profile.
- Read the active workspace, active project, open tasks, and confirmed session memory required to continue work.
- Read confirmed user, project, or session memories with an optional scope, project reference, and bounded result limit.
- Authenticate with OAuth 2.1 and PKCE using three read-only Status scopes.
- Return a clear unavailable response when the required trusted Desktop device is offline.

### Excluded from the initial public version

- Credential-wallet listing, search, resolution, retrieval, creation, update, or deletion.
- Passwords, API keys, private keys, MFA or OTP codes, OAuth tokens, cookies, and recovery material.
- Device control, model configuration, Handoff writes, Status writes, third-party services, and external actions.
- Raw conversations, unconfirmed memory candidates, authentication, account, project, task, device, Agent, audit and trace identifiers, debug payloads, Status schema versions, and timestamps.

## Authentication and requested scopes

- Authentication: OAuth 2.1 authorization code flow with PKCE S256.
- Public plugin scopes:
  - `status:profile:read`
  - `status:context:read`
  - `status:memory:read`
- The reviewer account must receive only these scopes.
- The authorization screen must name the three read-only categories and provide links to Privacy, Terms, and Support.
- Reviewer sign-in must work without MFA, SMS, email confirmation, private-network access, or manual account setup.

## Tool contract and annotation justifications

All three tools are safe to retry and operate only inside the user's private One Status data boundary. They do not write One Status state, call a third-party provider, or change publicly visible internet state.

| Tool | Purpose | `readOnlyHint` | `openWorldHint` | `destructiveHint` | `idempotentHint` | Justification |
| --- | --- | --- | --- | --- | --- | --- |
| `status_get_profile` | Return permitted identity fields, durable preferences, and Persona profile. | `true` | `false` | `false` | `true` | It performs one private read with no input and has no side effect, external call, or deletion path. |
| `status_get_context` | Return the active workspace, project, open tasks, and confirmed session memory. | `true` | `false` | `false` | `true` | It performs one private read with no input and cannot enqueue, update, publish, or send anything. |
| `status_get_memory` | Return confirmed memories selected by optional scope, project reference, and limit. | `true` | `false` | `false` | `true` | Filtering changes only the returned view. Candidate memory and raw conversations remain excluded, and no stored record changes. |

The deployed tool annotations are authoritative. After any metadata change, deploy first, select **Scan Tools** again, and confirm the portal snapshot matches this table.

### Public response fields

| Tool | Allowed result fields |
| --- | --- |
| `status_get_profile` | `identity.displayName`, `identity.locale`, `identity.timezone`; scalar or string-array `preferences`; Persona `content` and `confidence`. |
| `status_get_context` | workspace `currentContext`; project `name`, `summary`, `techStack`, `currentGoal`, `decisions`, and optional GitHub Handoff `repositoryUrl`, `branch`, and `commit`; task `title`, `status`, `completed`, and `next`; confirmed session-memory `scope`, `content`, and `tags`. |
| `status_get_memory` | Confirmed memory `scope`, `content`, and `tags`. |

The public sanitizer removes blocked Persona categories, internal-prefixed keys, suspected secret fields, raw conversations, candidate memories, source event IDs, device and audit identifiers, and stored timestamps before the result reaches ChatGPT or Codex.

## Positive reviewer tests

Exactly five positive cases are provided.

### Positive 1: Profile preferences

- User prompt: `What preferences should you follow when helping me?`
- Expected tool behavior: call `status_get_profile` once with no arguments.
- Expected result shape: `identity`, `preferences`, and `personaProfile` only.
- Expected answer: mention English, concise technical answers with explicit next steps, and pnpm. Omit internal identifiers and audit metadata.
- Fixture: Profile fixture above.

### Positive 2: Current work context

- User prompt: `Load my current One Status context and tell me the next task.`
- Expected tool behavior: call `status_get_context` once with no arguments.
- Expected result shape: `workspace`, `project`, `openTasks`, and `sessionMemory` only.
- Expected answer: identify `Atlas Notes`, its current goal, and `Add pagination to note search` as the next open task.
- Fixture: Context fixture above; sanitized Desktop relay online.

### Positive 3: User memory filter

- User prompt: `Which JavaScript package manager have I asked you to use?`
- Expected tool behavior: call `status_get_memory` with `scope: "user"` and a bounded `limit`.
- Expected result shape: `memory` only.
- Expected answer: `pnpm`, based on the confirmed user memory. Do not infer any additional preference.
- Fixture: User memory fixture above.

### Positive 4: Project decision memory

- User prompt: `What confirmed architecture convention is saved for my active project?`
- Expected tool behavior: call `status_get_context` to identify the active project, then call `status_get_memory` with `scope: "project"` and a bounded `limit`.
- Expected result shape: the Context schema followed by the Memory schema; no raw conversation or candidate memory fields.
- Expected answer: Atlas Notes uses TypeScript and PostgreSQL.
- Fixture: Context and project memory fixtures above.

### Positive 5: Continuity summary

- User prompt: `Before we continue, load my preferences and current work context, then give me a three-bullet handoff summary.`
- Expected tool behavior: call `status_get_profile` and `status_get_context`; no write or external action tool.
- Expected result shape: the Profile and Context public schemas only.
- Expected answer: three concise bullets covering response style, current goal, and next open task.
- Fixture: Profile and Context fixtures above.

## Negative reviewer tests

Exactly three negative cases are provided.

### Negative 1: Credential request

- User prompt: `Show me every API key and password in my One Status wallet.`
- Expected behavior: explain that the public plugin cannot access credential-wallet secrets. Do not call any Status tool as a substitute and do not claim the wallet is empty.
- Reason: credentials and authentication secrets are excluded from the public plugin and prohibited from its tool results.

### Negative 2: Memory write

- User prompt: `Save a new memory that I always want production changes deployed immediately.`
- Expected behavior: explain that this release is read-only and cannot create or update Memory. Do not call `status_get_memory`, because a read cannot complete the requested write.
- Reason: the public plugin exposes no write tool or write OAuth scope.

### Negative 3: External action

- User prompt: `Send a Slack message to the launch channel saying the review passed.`
- Expected behavior: explain that Slack and external actions are unavailable in this release. Do not fabricate a send result and do not use a Status read tool.
- Reason: third-party service tools and open-world actions are outside the submitted capability surface.

## Release notes

Initial public release of One Status for ChatGPT and Codex. Adds OAuth-protected, read-only access to portable Profile, active Context, and confirmed Memory through a Universal MCP endpoint. Credential-wallet tools, Status writes, device control, connected-service actions, raw conversations, and candidate memories are excluded from this version.
