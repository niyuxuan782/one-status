Privacy Policy

This policy explains the data handled by One Status, with a specific boundary for the first public One Status plugin available through ChatGPT and Codex.

1. Scope

One Status is operated by the verified developer identified in its public plugin listing. This policy covers the One Status website, account and synchronization services, Remote MCP authentication, and the first public One Status plugin for ChatGPT and Codex.

The One Status Desktop application also manages local device state and optional encrypted services. Where a Desktop feature has an additional notice or approval screen, that notice applies together with this policy.

2. First public plugin boundary

The public directory version is read-only.

It exposes only status_get_profile, status_get_context, and status_get_memory.

The public plugin can return a user-authorized view of portable Profile, active Context, and confirmed Memory. It cannot create, update, or delete data and cannot act on external services.

The public plugin does not request, read, collect, or return credential-wallet entries, passwords, API keys, private keys, MFA or OTP codes, access tokens, refresh tokens, session cookies, card data, or government identifiers. It also excludes raw conversations and unconfirmed memory candidates.

Credential tools, third-party action tools, device control, model configuration, and write operations are outside this first public plugin release and outside its OAuth grants.

4. How plugin data flows

  1. The user connects One Status through OAuth 2.1 with PKCE and approves the three read-only Status scopes.
  2. ChatGPT or Codex calls one of the three public tools after a relevant user request.
  3. An authorized One Status device decrypts only the selected Status view when a trusted device is required and available.
  4. The selected result passes through the Remote MCP service to OpenAI for display in the user's conversation.

Encrypted Status synchronization stores ciphertext in persistent cloud storage. During an authorized tool call, the One Status runtime and the connected client process the selected plaintext result transiently. When no eligible device is online, the service returns a clear unavailable status and does not return Status content.

5. Purposes of use

  • Authenticate the user and enforce the scopes they approved.
  • Return the minimum Profile, Context, or confirmed Memory needed for the user's request.
  • Maintain continuity across the user's devices and AI tools.
  • Prevent abuse, diagnose availability failures, and maintain security audit records.
  • Answer support, deletion, and privacy requests.

One Status does not sell personal data, use plugin data for targeted advertising, or use returned Status content to train a One Status model.

6. Categories of recipients

  • OpenAI: receives a tool result when the user asks ChatGPT or Codex to use One Status. OpenAI handles that data under the user's OpenAI relationship and settings.
  • Infrastructure providers: process encrypted storage, database, networking, and service traffic on behalf of One Status. Current production infrastructure uses Tencent Cloud for the dynamic service.
  • GitHub: serves the public website, documentation, source repository, and release downloads.
  • Authorities or professional advisers: receive limited data only when legally required or necessary to protect users, the service, or legal rights.

The first public plugin does not send Status results to GitHub, connected SaaS providers, data brokers, or advertising networks.

7. Retention timelines

  • Profile, Context, and Memory: retained until the user edits or deletes the item, closes the account, or requests deletion through support.
  • OAuth access tokens: expire after one hour. OAuth refresh tokens expire after 30 days unless refreshed or revoked. Expired or revoked token records are purged after a seven-day security window.
  • OAuth audit metadata: retained for 90 days, then purged, unless a longer period is required for an active security investigation or legal obligation.
  • Support communications: retained while the request is open and for up to 90 days after closure, unless the user asks for earlier deletion or a legal obligation requires longer retention.
  • Account closure: active service records are scheduled for deletion within 30 days after a verified request. Residual encrypted backups may remain until their normal overwrite cycle completes.

8. Your controls

  • Choose whether to connect One Status to ChatGPT or Codex.
  • Review the requested read-only scopes before approving OAuth access.
  • Revoke the plugin's OAuth grant from One Status or the connected OpenAI product.
  • View, edit, confirm, or delete Profile and Memory in One Status Desktop.
  • Keep a device offline, which prevents device-routed Status reads.
  • Request access, correction, export, account closure, or deletion by contacting support.

Some rights vary by location. One Status will verify the request before changing or disclosing account data.

9. Security

One Status uses encrypted transport, scoped OAuth grants, PKCE, separated Agent and device identities, encrypted Status storage, and metadata-only audit records. The public plugin exposes no credential tools. No system can guarantee absolute security; users should revoke access and contact support if they suspect unauthorized activity.

10. Changes

Material changes will be posted on this page with a new effective date. A future public plugin version that adds data categories or write capabilities will require an updated notice and the applicable OpenAI review process before publication.
